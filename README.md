# HackAIthon 2026 MVP

**Research-only** | **Diagnostic-only** | **Baseline ML-only** | **Human-review required**

This repository is a dedicated HackAIthon 2026 MVP workspace: a baseline ML model diagnostic framework for a banking stock-evaluation use case.

The use case remains a neutral banking stock-evaluation use case.

## What This MVP Is

This MVP is a static/local evidence diagnostic framework for baseline ML model review.

It is designed to show how a stock-evaluation system can organize model diagnostics, evidence, risk checks, and human-review routing without producing operational decisions.

Current scope:

- baseline ML models only
- static/local sample evidence only
- no Data Gateway in this sprint
- no live data
- no provider API calls
- no model training
- no model inference
- no benchmark rerun
- no action-oriented output
- human review required

## Engine Universe: What the 77k+ Specs Mean

The 77k+ number does not mean 77k trained models.

It is a generated diagnostic engine-spec universe. It proves that the MVP can manage many model configurations with deterministic IDs, static execution rules, safe skip behavior, and a clear path toward auxiliary, stack, risk, and evidence governance.

Current generated counts:

- Baseline engine specs: 32,850
- Auxiliary engine specs: 22,500
- Stack engine specs: 22,500

These are not performance claims, live-system claims, or profitability claims.

Each baseline engine spec represents a concrete diagnostic configuration such as:

```text
model_key + target + horizon + feature_set + policy
```

Each engine can run independently if matching static evidence exists. If evidence is missing, the engine returns a safe skip instead of fabricating output.

Auxiliary and stack engine specs are designed for later layers that combine, compare, or check outputs from baseline diagnostic engines.

## Local Storage Adapter

The MVP includes a local-only storage adapter for small normalized market-bar, diagnostic, evaluation, packet, report, and DAG-run tables.

It writes Parquet-compatible partition paths when a local Parquet engine is available. If no local Parquet engine is installed, it writes JSONL fallback files and reports the actual storage format in the write result.

This is not a server database, Data Gateway, provider integration, or live data ingestion layer.

Example:

```powershell
python -m src.hackaithon_mvp.local_storage.storage_cli --capability
```

## Hybrid Storage Architecture Contract

The MVP includes a compact hybrid storage architecture contract.

Current storage is the local partitioned file adapter with Parquet-compatible paths and JSONL fallback when no local Parquet engine is installed.

Target storage is a hybrid architecture with a canonical data lake, metadata store contract, analytical query adapter, and optional later serving layer. No server database, Data Gateway, provider integration, or serving database is implemented in this sprint.

Example:

```powershell
python -m src.hackaithon_mvp.hybrid_storage_architecture --section architecture
```

## Diagnostic DAG Runtime

The diagnostic DAG runtime makes the current diagnostic chain explicit as local/static DAG nodes:

```text
static_evidence_loader -> engine_runtime -> forecast_diagnostic_engine -> quant_core_policy_runtime -> scenario_engine -> risk_governance_engine -> decision_lane_engine -> market_context_engine -> calibration_engine -> research_allocation_view -> phase_router -> evidence_packet -> diagnostic_report
```

It provides a node registry, dependency validation, deterministic topological execution, local execution context, and runtime audit trail.

This is not an external workflow engine integration. It does not use Airflow, Prefect, Dagster, Celery, or provider-backed orchestration.

Example:

```powershell
python -m src.hackaithon_mvp.diagnostic_dag.dag_cli --ticker VCB --timeframe "1 ngày" --horizon-steps 1
```

## Storage-to-DAG Runtime Integration

The diagnostic DAG can optionally load compact local storage context from the local storage adapter and can optionally persist compact DAG, evidence packet, and diagnostic report records.

No storage read or write occurs by default. Storage integration requires explicit CLI flags or direct bridge-function calls with a local storage root.

This does not implement a server database, Data Gateway, provider integration, or live data ingestion layer.

Example:

```powershell
python -m src.hackaithon_mvp.diagnostic_dag.dag_cli --ticker VCB --timeframe "1 ngày" --horizon-steps 1 --storage-root .tmp_dag_storage --persist-run
```

## Actual Outcome Builder from Local Bars

The actual outcome builder derives realized future return, direction label, and actual timestamp from provided local forecast rows and local OHLCV bar rows.

It does not fetch live data, call provider APIs, or fabricate missing actual outcomes. If the current or future bar is unavailable, the forecast row is skipped.

Example:

```powershell
python -m src.hackaithon_mvp.actual_outcome_builder --forecasts path/to/forecast_rows.jsonl --bars path/to/bar_rows.jsonl --evaluate
```
